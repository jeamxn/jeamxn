# 내용별 3D 모델

`apps/web/app/feature/home/story-chapter-models.ts`는 홈 이야기를 위한
독립 모델 세트를 만든다. 장면을 바꿀 때 같은 여덟 아이콘의 위치만 바꾸지 않고,
학교·어드민·AI 도구 연결·통합 에이전트의 주 오브젝트 자체가 바뀐다.

## 생성 API

```ts
createChapterModels(): {
  id: StoryChapterId;
  models: { id: string; group: Group }[];
}[]
```

`StoryChapterId`는 `app/shared/lib/scroll-story.ts`의 타입이다.
이 파일은 메시·재질만 만들며 카메라, 렌더러, 시계, 애니메이션은 만들지 않는다.
렌더러가 한 번 생성해 유지하고, 해당 장면 또는 전환 중인 두 장면만 보이게 한다.
주 오브젝트를 크게 보여 주는 크기 차이와 합쳐지는 동작도 렌더러/포즈 계층에서 정한다.

| 장면 | 모델 ID (이 순서) | 주 오브젝트와 구분 |
| --- | --- | --- |
| intro | `idea`, `document` | 반투명 전구와 두께 있는 폴더 |
| dipull | `campus`, `music`, `laundry`, `calendar` | 세이지색 지붕의 2층 학교, 8개 교실 창·시계탑·현관·캐노피·계단; 학교 생활 기능을 주변에 배치 |
| internal | `admin-left`, `admin-center`, `admin-right`, `shield`, `key`, `dpd` | 표·통합 모듈·프로필로 내용과 색이 다른 콘솔 3개, 두꺼운 잠금 방패와 열쇠, DPD 차트 노트북 |
| ax | `lily`, `mcp-server`, `tool-plug`, `meeting`, `presentation` | 라벤더색 둥근 어시스턴트 독, 탈착 트레이·포트가 있는 서버, 케이블 달린 입체 플러그, 대화, 발표 보드와 마이크 연단 |
| ara | `agent`, `document`, `calendar`, `tool-plug`, `canvas` | 파란색 통합 허브, 앞면의 솟은 평행 물결 3개, 측면·윗면 연결 포트와 원형 독, 문서·일정·도구·작업 캔버스 |

학교는 특정 학교 건물의 복제물이 아니다. Lily는 실제 브랜드 캐릭터를 주장하지 않는
일반 어시스턴트 모델이다. 발표 보드는 막대와 선으로 의미만 표현한 모형이지 실제
사내 발표 화면이 아니다. ara 앞면도 사용자가 확인한 물결 방향을 직접 만든 튜브로
표현한 것이며 비공개 제품 자산을 옮기지 않았다. 외부 모델·이미지·폰트·텍스처가 없다.

## 좌표와 리소스 계약

- 각 모델 루트의 이동/회전은 0, 크기는 1이다. 정면은 +Z, 위는 +Y다
- 자식 content만 정규화한다. 전체 AABB 중심은 0, 가장 긴 변은 2다
- 각 모델은 4개 이상 메시로 이루어지며 모든 모델에 실제 깊이가 있다
- 반복 창·표시등·접점 등은 `InstancedMesh`로 묶는다
- `group.userData`에 `kind`, `chapter`, `front`, `up`, `modeling`을 제공한다
- `createStoryModel(name: StoryTool): Group`은 필요한 레거시 모델 하나만 만든다
- `createStoryModels()`는 기존 8개 순서와 공유 재질을 유지하는 호환 API다
- 모델 팩토리는 사용하지 않은 팔레트 재질을 즉시 해제한다. 반환 모델에는 공유 재질이
  있으므로 소유자가 전체를 순회해 `Set`으로 기하·재질을 중복 제거한 뒤 각각 해제한다
- 장면마다 호출해 다시 만들거나 전환 때마다 모델을 버리지 않는다

## 기하 비용 실측

2026-10-18 회사맥 Node 24.16.0, Three 0.186.1에서 인스턴스 수까지 계산했다.
삼각형은 실제 인스턴스 수를 곱했고, mesh 수는 기본 패스의 draw 호출 상한이다.
작은 글줄·창살·접점은 그림자를 받되 드리우지 않고, 큰 구조물만 그림자를 드리운다.
그림자·후처리 등 추가 패스는 렌더러 설정에 따라 별도로 더해진다.

| 장면 | 모델 | 메시 | 삼각형 | 그림자 구조물 |
| --- | ---: | ---: | ---: | ---: |
| intro | 2 | 21 | 10,260 | 3 |
| dipull | 4 | 54 | 19,568 | 13 |
| internal | 6 | 65 | 14,936 | 17 |
| ax | 5 | 53 | 16,496 | 14 |
| ara | 5 | 53 | 14,136 | 11 |
| 합계 | 22 | 246 | 75,396 | 58 |

한 장면의 최대치는 65메시/19,568삼각형이다. 인접 두 장면을 전부 동시에 그려도
최대 119메시/34,504삼각형이다. 기본 패스 + 방향광 그림자 패스를
합쳐도 인접 두 장면 모델은 최대 149 draw다. 바닥·연결선·추가 효과의 호출은
이 수치에 들어 있지 않으므로 통합 브라우저에서 `renderer.info`로 확인한다. 전체 세트를 항상 보이게 두면 246메시가 되므로
반드시 비활성 장면을 숨겨야 한다. 팩토리에 애니메이션/idle render loop는 없다.

## 소스 단위 검사

비공개 임시 검사 스크립트와 결과는 `/tmp/jeamxn-scenes-2157/`에만 두었다.
검사 항목은 다음과 같다.

- 장면 5개와 모델 ID 22개, 순서가 계약과 완전히 같음
- 모든 루트 identity, AABB 중심 오차 < 0.00001, 가장 긴 변 2
- 모델마다 4개 이상 메시, 모든 좌표 유한값
- 모든 기하 노멀이 유한값·단위 벡터, 퇴화 삼각형 0개
- 모든 모델의 기하와 재질을 순회해 중복 해제 가능
- 기존 8개 레거시 모델 검사 2개 통과
- 해당 두 소스 파일 Biome 검사 통과
- 웹 `tsc --noEmit` 통과

브라우저에서의 실루엣·화면 점유율·회전·역스크롤·GPU 해제·모바일 검증은
