# Design direction

Subject: Jeamin is a product maker, not a stack checklist. Let a visitor meet the person, then inspect the products, then ask or get in touch.

## Compact system
- Fog `#f7f8fa`: calm background, not cream. Paper `#ffffff`: media and controls. Ink `#20262b`: type and contact area. Slate `#627079`: supporting copy. Cobalt `#2459d3`: actionable moments. Mist `#dfe6eb`: quiet structure.
- Wanted Sans: Korean editorial/body, clear and warm. Geist: oversized English name and project names. Locally bundled OFL fonts, never the references' proprietary font.
- Left aligned text. A 1280px editorial container with fluid gutters; uneven text/image proportions rather than identical card grids. Larger spacing separates stories, thin rules only separate project metadata and history.

```
[jeamxn]                                  [작업 / 소개 / 이력] [대화]
[제품을 만드는 최재민입니다]               [large tall portrait]
[brief human introduction]                 [                   ]
[work link]                                [                   ]
[            JEAMIN CHOI oversized, anchored to portrait        ]
[Selected work]                       [why these products matter]
[wide ara product scene]       [name / story / role / detail link]
[Dipull story]                 [wide school product scene       ]
[more work as descriptive rows, not tiles]
[short personal story / invitation]
[dark contact area: 함께 만들 이야기가 있나요? / email]
```

On mobile: name wraps into two intentional lines, intro above a tall portrait, work image above its story, useful metadata stacked. Menu and assistant are native modal dialogs with keyboard focus containment, Escape, restored focus, and scroll locking.

## Review against brief
Rejected the default centered slogan plus small portrait and badge statistics: the person is the memorable element. Rejected a uniform rounded project grid: ara and Dipull have different human stories and deserve generous editorial scenes. No gradients/metrics/numbered decoration. Glass is limited to the assistant trigger/panel. Accent only signals interaction. Company contribution is text-only public material, not private product screenshots.

Media samples are labeled “가상 데이터로 재구성한 화면”. Curated packages/core content is the only public factual source; the website, resume and assistant share it. Motion is a single restrained hero entrance plus direct interaction feedback, fully disabled under reduced motion.

## Implementation and verification

- Features are isolated under `app/feature/{home,about,work,resume,assistant,shell}`. Thin routes compose the imported core data. Shared widgets own portrait and sample scenes; packages own original tokens, SVG icons and native dialog primitives.
- CSS uses zero-specificity `:where()` component selectors so breakpoint order is explicit and no higher-weight selector silently defeats later responsive styles. Tailwind 4 owns theme variables; custom editorial compositions use those tokens.
- The actual selected portrait is intentionally cropped tall with its face centred and the English name across its lower edge. Photo source is landscape 1800×1200; mobile uses its 720w derivative.
- ara and Dipull previews, secondary editor/mobile examples, and a user-triggered silent ara video are labeled virtual product examples. No private ara implementation or company screens are copied. The media asset pipeline is owned by the separate media session.
- First QA found Chrome native dialog keyboard Tab could reach body after a complete cycle. Added explicit first/last focus wrapping, then verified at every viewport. Escape closes, previous focus restores, body overflow restores and no mobile auto-focus summons the keyboard.
- Chrome headless QA: 390/768/1440px × 9 actual routes (home, about, six projects, resume), 27 successful visits. No horizontal overflow, decoded-image failure or page runtime exception. Lazy images are scrolled into view and decoded before inspection. Reduced-motion computes no hero animation. 19 screenshots and geometry results are in `/tmp/jeamxn-renewal/web-qa`.
- Assistant QA uses deterministic mocked responses, no real AI key: offline explicit canned FAQ, AI loading, 429 inline error and preserved draft, max 10 questions, max 10 wire messages, context truncation, HTML/executable links/images rejected, reset, missing project and close-abort/reopen. Real local backend status/PDF endpoints were independently reached with HTTP200, but full AI provider integration is not claimed.
- Owned packages+web build and typecheck pass; web unit tests 3/3, owned strict Biome and architecture boundary check pass.
- Screenshots were generated by actual Chrome. In this child session, no image-viewing tool is available and drive_push failed with device-server URL mismatch; geometry/DOM assertions are confirmed, but a human/parent visual screenshot critique remains desirable.
- No commit, push, merge, deploy or production change was performed. A typegen tool automatically added `isbot@5` to the web manifest and refreshed lock; the root owner was notified for final lock consistency review.
