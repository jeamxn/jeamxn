# Design direction

Subject: Jeamin is a product maker, not a stack checklist. Let a visitor meet the person, then inspect the products, then ask or get in touch.

## Compact system
- Fog `#f7f8fa`: calm background, not cream. Paper `#ffffff`: media and controls. Ink `#20262b`: type and contact area. Slate `#627079`: supporting copy. Cobalt `#2459d3`: actionable moments. Mist `#dfe6eb`: quiet structure.
- Wanted Sans: Korean editorial/body, clear and warm. Geist: oversized English name and project names. Locally bundled OFL fonts, never the references' proprietary font.
- Left aligned text. A 1280px editorial container with fluid gutters; uneven text/image proportions rather than identical card grids. Larger spacing separates stories, thin rules only separate project metadata and history.

```
[jeamxn]                                  [작업 / 소개 / 이력] [대화]
[제품을 만드는 최재민입니다]               [large tall portrait]
[brief human introduction]                 [                   ]
[work link]                                [                   ]
[            JEAMIN CHOI oversized, anchored to portrait        ]
[Selected work]                       [why these products matter]
[wide ara product scene]       [name / story / role / detail link]
[Dipull story]                 [wide school product scene       ]
[more work as descriptive rows, not tiles]
[short personal story / invitation]
[dark contact area: 함께 만들 이야기가 있나요? / email]
```

On mobile: name wraps into two intentional lines, intro above a tall portrait, work image above its story, useful metadata stacked. Menu and assistant are native modal dialogs with keyboard focus containment, Escape, restored focus, and scroll locking.

## Review against brief
Rejected the default centered slogan plus small portrait and badge statistics: the person is the memorable element. Rejected a uniform rounded project grid: ara and Dipull have different human stories and deserve generous editorial scenes. No gradients/metrics/numbered decoration. Glass is limited to the assistant trigger/panel. Accent only signals interaction. Company contribution is text-only public material, not private product screenshots.

Media samples are labeled “가상 데이터로 재구성한 화면”. Curated packages/core content is the only public factual source; the website, resume and assistant share it. Motion is a single restrained hero entrance plus direct interaction feedback, fully disabled under reduced motion.

## Implementation and verification

- Features are isolated under `app/feature/{home,about,work,resume,assistant,shell}`. Thin routes compose the imported core data. Shared widgets own portrait and sample scenes; packages own original tokens, SVG icons and native dialog primitives.
- CSS uses zero-specificity `:where()` component selectors so breakpoint order is explicit and no higher-weight selector silently defeats later responsive styles. Tailwind 4 owns theme variables; custom editorial compositions use those tokens.
- The actual selected portrait is intentionally cropped tall with its face centred and the English name across its lower edge. Photo source is landscape 1800×1200; mobile uses its 720w derivative.
- ara and Dipull previews, secondary editor/mobile examples, and a user-triggered silent ara video are labeled virtual product examples. No private ara implementation or company screens are copied. The media asset pipeline is owned by the separate media session.
- First QA found Chrome native dialog keyboard Tab could reach body after a complete cycle. Added explicit first/last focus wrapping, then verified at every viewport. Escape closes, previous focus restores, body overflow restores and no mobile auto-focus summons the keyboard.
- Chrome headless QA: 390/768/1440px × 9 actual routes (home, about, six projects, resume), 27 successful visits. No horizontal overflow, decoded-image failure or page runtime exception. Lazy images are scrolled into view and decoded before inspection. Reduced-motion computes no hero animation. 19 screenshots and geometry results are in `/tmp/jeamxn-renewal/web-qa`.
- Assistant QA uses deterministic mocked responses, no real AI key: offline explicit canned FAQ, AI loading, 429 inline error and preserved draft, max 10 questions, max 10 wire messages, context truncation, HTML/executable links/images rejected, reset, missing project and close-abort/reopen. Real local backend status/PDF endpoints were independently reached with HTTP200, but full AI provider integration is not claimed.
- Owned packages+web build and typecheck pass; web unit tests 3/3, owned strict Biome and architecture boundary check pass.
- Screenshots were generated by actual Chrome. In this child session, no image-viewing tool is available and drive_push failed with device-server URL mismatch; geometry/DOM assertions are confirmed, but a human/parent visual screenshot critique remains desirable.
- No commit, push, merge, deploy or production change was performed. A typegen tool automatically added `isbot@5` to the web manifest and refreshed lock; the root owner was notified for final lock consistency review.

## React Bits layer (2026-11-20)

All 219 React Bits components were reviewed; eight are used, each where it answers something the
visitor does. The scroll story, palette and type scale are unchanged.

- PillNav: the desktop menu is a glass pill with a gliding highlight and a cobalt dot on the current page.
- Magnet: the brand, the contact button, round project arrows, the next-story arrow and the footer mail button lean toward the pointer.
- DotGrid: a quiet dot field behind the opening scene bends around the pointer and leaves with the scene.
- ScrollVelocity: one band of project names between the story and the work list moves with scroll speed.
- GlareHover: a sheen crosses the ara and Dipull screens in the direction the pointer moves.
- ScrollReveal: the closing statement on the home page sharpens word by word as it is scrolled into view.
- VariableProximity: the footer question gains weight and width near the pointer, using the site's own variable font.
- Threads: fine cobalt lines drift behind the footer heading and part around the pointer.

Rejected: SplitText/BlurText page-title entrances (they hide prerendered text until JS runs), card
kits (SpotlightCard, MagicBento) that would turn stories into identical tiles, and cursor
replacements. Reduced motion removes the dot field and threads and stills the rest.

## React Bits layer, second pass (2026-11-20)

The owner asked for most of the library, for fun, spread over the real pages and not gathered on a
showcase page. All 219 components are vendored; 215 mount on some page, each carrying that page's own
content: project names, the portrait, published product screens, real links. Nothing is labelled with
a component name and there is no sample copy. The scroll story, palette and type scale are unchanged.

Where they are:

- Shell: PillNav, Magnet, a cobalt ClickSpark on every click, and in the footer Threads,
  VariableProximity, a large TextPressure `jeamxn`, CircularText around the mail button and a faint
  Noise grain.
- Home, after the story: three product cards and a grid of what was done in each; the product screens
  on one stage with a single "show it another way" button (21 layouts); a band of the site's sentences
  and project names in motion; the asterisk mark in metal, glass and light; and a staff badge on a
  Lanyard beside the closing statement.
- Work list: the project names on a curved loop under the heading. Search and filters stay in the
  first screen.
- Work record and activity pages: a record with no product screen opens with a cover, dealt out by the
  record's place in the list from three decks (`shared/widget/cover.tsx`): one of 65 backgrounds, the
  record's name in one of 20 text animations, and on every other record one of 13 pointer effects that
  lives inside the cover. Every record ends with who made it (the portrait, one of 17 treatments per
  record) and a way onward (one of 9 menus or 2 pickers per record, with the site's real
  destinations).
- ara record: what you do in ara, by hand: talking to the agent, adjusting a canvas, tidying documents.
- Dipull record: what students did in Dipull, by hand: booking a washer, choosing the wake-up song.
  Both records say plainly that the pieces are rebuilt for the page and connected to nothing.
- Resume: CountUp counts taken from the data, a LogoLoop of the most used tools, the Lanyard badge,
  and the portrait on one stage with the same single button.
- Not found: a FuzzyText 404, a menu of real destinations, mail and work-list buttons, and a few
  toys. The real HTTP 404 page is
  the app shell, so it shows the same screen.

Left out because no page had a natural place for them: RubberSegment, CurvedInput, FadeContent and
GradualBlur.

Rules that keep it from breaking:

- `Bit` (`shared/widget/bit.tsx`) mounts a component only while its box is near the viewport and
  unmounts it when it leaves, behind an error boundary. Browsers cap live WebGL contexts, so heavy
  groups share one stage, and a component that cannot start shows a short message instead of taking
  the page down.
- Nothing from the library renders during prerender. Static HTML carries headings and copy; where a
  number or a list matters (resume counts and tools) the plain version is the placeholder. Covers and
  the word band are decorative and hidden from assistive technology; the heading above says the same.
- Tailwind utilities live in cascade layers and lose to the unlayered element rules in `app.css`.
  Inside `.bit`, those element rules are handed back with `revert-layer`.
- Reduced motion: covers stay a still gradient with the name, the site-wide spark is off, and pieces
  that run on their own wait behind a button. Pointer effects need a fine pointer.
- `pnpm test:bits` (`scripts/verify-bits.mjs`) walks every page under the production CSP, scrolling
  to the end and pressing every "show it another way" button, and fails on a page error, a console
  error, an off-origin request, a component that did not start, horizontal overflow, more than 12
  live WebGL contexts, or fewer than 180 components in use.
- No camera, microphone or network: ReflectiveCard runs with `webcam={false}`, VoicePill with a
  simulated level, GridScan without face tracking, and the agent pieces change state on timers.
